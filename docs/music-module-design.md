# 音乐模块设计

## 数据流

1. 搜索结果保留歌曲来源、ID、标题、歌手和封面。
2. 播放歌曲后建立歌词候选列表：当前歌曲优先，其次是搜索结果中的同名同歌手项目。
3. 每个候选通过现有公开歌词接口请求，失败后自动尝试下一个候选。
4. 原文、翻译和罗马音分别解析为带时间戳的行，再按时间戳合并。
5. 合并后的 `QVariantList` 暴露给 QML；原始歌词以 JSON 文件缓存。

## 缓存

- 目录：应用数据目录下的 `cache/music-lyrics`。
- 键：来源、歌曲 ID、标题和歌手的 SHA-256。
- 内容：原文、翻译、罗马音、实际来源和保存时间。
- 有效期：30 天。

## UI

- 左栏：来源切换、搜索框、紧凑歌曲列表。
- 右栏：当前歌曲信息、播放操作、音量和歌词。
- 歌词工具条：来源状态、重新匹配、偏移减/归零/加、桌面歌词。
- 桌面歌词使用顶层透明工具窗口，显示当前行及翻译。
